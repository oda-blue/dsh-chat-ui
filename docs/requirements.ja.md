# dsh-chat-ui 要件定義（レビュー用）

このドキュメントは、`dsh-chat-ui` の実装を**第三者（別の AI や人）がレビューする**ための要件定義です。
「何を満たすべきか」「何を満たしたと確認済みか」「何が既知の制約か」を分けて書いています。

- 対象バージョン: `0.1.0`
- 対象環境: DSH（DeepSeek Harness）`0.2.1-rc.5` の **web プロファイル**
- 実装の詳細な経緯・落とし穴: リポジトリ外の `NOTES.md`（このリポジトリには含まない）

---

## 1. 背景と目的

ChatGPT はチャットと Codex で利用上限を共有している。日常のチャットで上限を消費したくないため、
DSH の web UI を ChatGPT の代わりに常用したい。

そのために、DSH の web UI を**チャット中心の画面**に寄せ、**PC とスマホの両方から気軽に使え**、
**GitHub で配布できて誰でも簡単に導入できる**形にする。

### 非目標（やらないこと）

- DSH 本体の改変（`node_modules` の書き換え、パッチ当て）
- モデルの鍵・API 設定の同梱や管理
- 外部公開（インターネットへの露出）、認証基盤の提供
- 複数ユーザー・権限管理

## 2. 前提と制約

| 項目 | 内容 |
|---|---|
| 対象 | DSH web プロファイルのみ（headless / tui は対象外） |
| 実装形態 | クライアントプラグイン（CSS と小さな JS）＋ホスト側の小さな処理 |
| 依存 | Node.js 20 以上。追加の npm 依存は無し |
| 配布 | GitHub リポジトリ（そのまま `dsh plugin add` できる形）と Release の tarball |
| 秘密情報 | リポジトリ・パッケージに鍵、API 設定、個人パス、`$DSH_HOME` 配下を含めない |

### 用語

- **ワークスペース**: DSH の概念。セッションが属する実フォルダで、エージェントの cwd と書き込み範囲。
- **入口（entrance）**: 固定 URL で待ち受け、DSH 本体へ中継する小さなサーバー（`bin/web-entry.mjs`）。
- **アクセスモード**: 読み取り専用 / ファイルへの書き込み / フルアクセス / 自動レビュー。

## 3. 機能要件

### FR-1 テーマ（ChatGPT 風）

- 配色・面・文字色を ChatGPT 風にする（ダーク: 地 `#212121` / サイドバー `#171717` / コンポーザ `#303030` / 文字 `#ececec`）。
- ライトも用意する。
- **DSH 本体の CSS は書き換えない**。`--dsw-*` トークンの上書きで実現する。

### FR-2 履歴とサイドバー

- 履歴は**更新順のフラットな 1 リスト**を既定にする（ワークスペース別の箱を出さない）。
- サイドバーの見出しは「チャット」。
- ワークスペースの**選択・追加**を UI から出さない。
- 「新しいチャット」は**枠なしの行**にする（ChatGPT と同じ）。
- 上部の開発者向けナビ（プラグイン / 自動化タスク / その他）を出さない。

### FR-3 右サイドバー

- 右サイドバー（実行の記録・ブラウザ・ファイル・ターミナル・ドキュメントプレビュー）の**入口を出さない**。
- 何らかの理由で開いた場合は**閉じられる**こと（閉じる操作を隠さない）。

### FR-4 会話ヘッダー

- ChatGPT と同じ **1 行**（チャットの題名と `⋯` の「その他の操作」）にする。区切り線も出さない。
- エージェントチーム / Standard モード / サブエージェント件数のチップを出さない。
- 表示の切り替えタブ（チャット / 実行の記録 / その他の会話の表示）と「エクスプローラーで開く」を出さない。
  別のタブが選ばれたまま開いた時は、チャットのタブへ戻す（戻る手段が無くならないように）。
- 途中経過は会話の中に出る（「リクエストを分析中」→「分析が完了しました」、ツールの行、思考の折りたたみ）。

### FR-5 コンポーザ

- アクセスモード（書き込み権限）は**アイコンだけ**で常時表示する。モード名はホバー（`title`）と読み上げ（`aria-label`）で分かる。
- モデル選択は常時「**モデル**」表示。実名と思考の強度は `title` / `aria-label` / メニュー内で分かる。
- 入力欄のプレースホルダは「何でも聞いてください」「メッセージを送信」。
- 入力欄の下の数字の行（ターン・ステップ・トークン/秒、使用トークン・キャッシュヒット、文脈の使用率）を出さない。
  そのぶん入力欄の下に余白をとる（PC 14px、スマホ 12px かホームバー分）。

### FR-6 スマホ（幅 ≤ 768px）

- 左の 56px レールをやめ、サイドバーを**オーバーレイのドロワー**にする。
- 中央（チャット）は**全幅**。コンポーザも全幅。
- 左上にハンバーガー。背景クリック / Esc / 画面遷移で閉じる。
- 開いたらフォーカスをドロワーの中（閉じるボタン）へ移し、開いている間は裏の会話を `inert` にする。
  閉じたらハンバーガーへ戻す。ハンバーガーは `aria-expanded` で開閉を伝える。
- 背景は暗幕で減光する。
- iPhone のホームバー余白、入力時のズーム防止（16px）に対応する。

### FR-7 作業フォルダ（新規チャットの固定）

- 起動時に作業フォルダ（既定 `$DSH_HOME/chat`、設定 `chatWorkspacePath` で変更可）を**作成し、DSH に登録**する。
- 新規チャットは**常にそのフォルダ**で作る（「最後に使ったワークスペース」に流れない）。
- フォルダの名前は自由。ホスト側がワークスペースの名前を `chat (dsh-chat-ui)` にして印を付け、
  クライアント側はその名前で探す（DSH はワークスペース名の重複を許さないので 1 つに決まる）。
  設定を変えた時は、前のフォルダの名前を元に戻す。印が無い時だけフォルダ名 `chat` で探す。
- 既存セッションの所属は変えない。

### FR-8 日本語

- 日本語の言語パックと日本語優先のフォント指定を**同梱**する。
- 文言は ChatGPT 風（「何をお手伝いしましょうか？」「新しいチャット」「チャット」）。
- 他の日本語パック（例: `@local/dsh-ja`）が既に入っている場合は**二重登録しない**。

### FR-9 入口（PC・スマホ）

- `--host lan` で LAN の IPv4 を自動検出して待ち受ける。
- **固定 URL**（既定 `:8123`）で待ち受け、DSH へ中継する。URL は起動ごとに変わらない。
- token は URL に出さない（入口が内部で認証する）。
- 旧 `:8124` の URL は入口へ**転送**する（古いブックマーク・ホーム画面を救済）。
- `<PC名>.local` でも開ける（IP が変わってもブックマークが生きる）。
- **他のサイトから使わせない**: 入口自身のアドレス宛て以外の Host（DNS rebinding）と、他サイトの
  `Origin` / `Sec-Fetch-Site: cross-site` を断る。ヘッダーは書き換えずに DSH へ渡し、DSH 本体の検査も効かせる。
- **登録した端末だけ使える**: この PC（ループバック）以外は、8 桁のパスコードで 1 回登録する。
  登録は署名付き cookie（HttpOnly・SameSite=Strict）で、入口の再起動後も有効。間違いは回数制限する。
  パスコードと署名鍵は `$DSH_HOME/dsh-chat-ui/entry-pairing.json` に置き、`--reset-pairing` で作り直せる。
- `--mode redirect`（token 付き URL へ 302）はループバック専用。LAN の指定では起動を拒否する。
- **ホーム画面のアプリ**: プロキシの入口は `/manifest.webmanifest`（名前「DSH チャット」/ "DSH Chat"、`display: standalone`、
  色 `#212121`）と PNG アイコン（`/apple-touch-icon.png` 180px、192 / 512 / maskable 512）を返す。DSH 自身の manifest は
  `fullscreen` で SVG アイコンだけのため差し替える。ブラウザは cookie なしで取りに来るので登録前でも返す（Host・送信元の検査は通常どおり）。
  iPhone 向けに、DSH のページ（ページ読み込みの HTML だけ）へ `apple-mobile-web-app-capable` などのタグとアイコンのリンクを足す。
  Android の独立アプリ化は安全なアドレスが必要なので、Chrome の `unsafely-treat-insecure-origin-as-secure` に入口のアドレスを入れる手順を README に書く（入口は HTTP のまま）。

### FR-10 可逆性・配布

- プラグインを外すと元の DSH の UI に戻る。
- GitHub から `dsh plugin --profile web add github:oda-blue/dsh-chat-ui` で入る。
- tarball（`npm pack`）からも入る。
- README（日英）、5 分の導入手順（`docs/quickstart*.md`）、LICENSE（MIT）を同梱する。

## 4. 非機能要件

| ID | 要件 |
|---|---|
| NFR-1 | **DSH 本体を書き換えない**（更新に強い）。CSS はローカル名（`[class*="sessionRow"]` 等）で当てる |
| NFR-2 | 秘密情報を扱わない・同梱しない。テレメトリは入口経由の起動で既定無効を渡す。LAN 前提で、外部公開しない。入口は DSH の Host/Origin 検査を弱めない（書き換えて素通りさせない） |
| NFR-3 | ストリーミング中の DOM 監視で重くならない（間引き 150ms） |
| NFR-4 | 読み上げ・キーボード操作を壊さない（`aria-label` 維持、閉じたドロワーは `inert`、開いたドロワーにフォーカスを閉じ込める、キーボードのフォーカス枠を消さない、`prefers-reduced-motion` 対応、補助文字は背景の上で 4.5:1 以上） |
| NFR-5 | Windows / macOS / Linux、Node 20 以上で動く |
| NFR-6 | 変更はすべて CSS/JS の上書きで、戻し手順を文書化する |

## 7. 既知の制約・トレードオフ（レビューで特に見てほしい点）

1. **DSH のクラス名はハッシュ付き**（例 `pI_x6G_frame`）。CSS はローカル名の部分一致で当てており、
   上流がローカル名を変えると当たらなくなる。`data-dshgpt-*` を付ける JS も同様。
2. **作業フォルダはワークスペースの名前（`chat (dsh-chat-ui)`）で見つける**。クライアントに設定が渡らないための工夫で、
   元の DSH の画面や TUI でもこの名前で見える。利用者が名前を変えても、次の起動でホスト側が付け直す。
3. **サイドバーの開閉状態は DSH の設定として保存**されるため、スマホでドロワーを閉じると PC でも畳まれた状態で開くことがある。
4. **アクセスモードとモデル名を常時非表示**にしている。安全性・情報量とのトレードオフで、`title` と `aria-label` で補っている。
   入力欄の下の数字の行（文脈の使用率を含む）も出さないので、会話が長くなって文脈が埋まりかけても画面からは分からない。
5. **右パネル内の機能**（ブラウザ / ワークスペースのファイル / ターミナル / ドキュメントプレビュー）は入口が無い。
6. **プラグイン管理 UI**（一覧・追加/削除）も入口が無い。CLI と「設定 → 内蔵プラグイン」で代替。
7. **クライアント側の `apply(ctx, config)` には設定が渡らない**（実測。ホスト専用）。そのためパスはホスト側で扱い、ワークスペースの名前を印にしてクライアントへ伝える。
8. **入口はリバースプロキシ**。以前は `Host` / `Origin` / `Sec-Fetch-Site` を上流に合わせて書き換えていたが、
   これは DSH の DNS rebinding・クロスサイト対策を無効にしていた（任意のサイトから WebSocket で owner 権限に届いた）。
   今は書き換えず、入口の authority を `--trusted-host` で DSH に信頼させる。DSH の cookie は Host ごとに発行されるので、
   入口は authority ごとに token から cookie を取り、401 なら取り直す。
9. **LAN の入口は token を内部付与する**ので、入口に到達できれば owner 権限（ファイル操作・コマンド実行を含む）になる。
   そのため PC 以外はパスコードで登録した端末に限る。ループバックからの接続は登録不要（この PC 上のプロセスは
   もともと同じ利用者の権限で動くため）。家庭内 LAN 前提で、ポート開放はしない。
10. **未検証**: 実機スマホ（Android はアプリとしてインストールできたが、HTTP のため Chrome のフラグが必要）、英語・中国語ロケール、DSH 更新後の追随。
    GitHub からの `dsh plugin add github:oda-blue/dsh-chat-ui` は 2026-11-05 に確認済み（非公開リポジトリ、一時の DSH_HOME で導入 → 画面にプラグインが効き、`$DSH_HOME/chat` が `chat (dsh-chat-ui)` で登録された）。
